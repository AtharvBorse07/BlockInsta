1. OBJECTIVE
------------

Build BlockInsta, a privacy-friendly browser extension that helps an iPhone user avoid Instagram by blocking Instagram's website in Safari.

The first release should:

- Work as a Safari Web Extension on iPhone.
- Block visits to Instagram web URLs.
- Replace a blocked visit with a clear, locally hosted block page.
- Let the user enable or disable blocking from an extension popup.
- Allow an optional temporary unlock, after which blocking automatically resumes.
- Store all settings locally. No account, server, analytics, or remote database is required.
- Keep the WebExtension source compatible with desktop Chrome and Brave wherever their supported APIs permit.


2. IMPORTANT PLATFORM CONSTRAINTS
---------------------------------

- Safari supports web extensions on iPhone beginning with iOS 15.
- Chrome on iPhone does not run Chrome Web Store extensions.
- Brave on iPhone does not support ordinary third-party Chromium extensions.
- Therefore, Safari is the iPhone target.
- The same standard WebExtension source can also be packaged for desktop Chrome and Brave.
- A browser extension can block instagram.com inside the browser, but it cannot block the native Instagram iOS app.
- Blocking the native Instagram app would be a separate phase using Apple Screen Time / Family Controls capabilities or another device-level approach.
- Apple currently allows Safari Web Extensions to be packaged through App Store Connect from a web browser without requiring a Mac or Xcode.
- An Apple Developer Program membership and App Store Connect access are required to package and distribute the iPhone extension through TestFlight or the App Store.

Official references:

- Safari Web Extensions:
  https://developer.apple.com/documentation/safariservices/safari-web-extensions
- Packaging through App Store Connect:
  https://developer.apple.com/documentation/safariservices/packaging-and-distributing-safari-web-extensions-with-app-store-connect
- Chrome mobile extension limitation:
  https://support.google.com/chrome_webstore/answer/1698338
- Brave extension documentation:

3. MVP SCOPE
------------

Required:

1. Block these hosts and their subdomains:
   - instagram.com
   - www.instagram.com
   - m.instagram.com

2. Cover normal Instagram page navigation, including URLs such as:
   - https://www.instagram.com/
   - https://www.instagram.com/reels/
   - https://www.instagram.com/explore/
   - https://www.instagram.com/direct/
   - https://www.instagram.com/<username>/

3. Redirect blocked top-level navigation to an extension-owned page.

4. Block page content:
   - Product name: BlockInsta
   - Short message explaining that Instagram is blocked intentionally.
   - Button to return to the previous page or close the tab when supported.
   - Button for a temporary unlock.
   - Display the remaining unlock time while an unlock is active.

5. Popup controls:
   - Main enabled/disabled switch.
   - Temporary unlock choices: 5, 15, and 30 minutes.
   - Re-enable now button when temporarily unlocked.
   - Clear status text showing whether blocking is active.

6. Local persistence:
   - Store enabled state.
   - Store the temporary unlock expiration timestamp.
   - Automatically restore blocking when the timestamp expires.

7. Privacy:
   - No telemetry.
   - No network requests made by the extension.
   - No browsing history collection.
   - Request access only to Instagram URLs and the minimum extension APIs needed.

Optional only after the MVP works:

- Daily or weekly blocking schedule.
- Custom motivational message.
- Block-attempt counter stored locally.
- Additional distracting websites.
- Password or delay before disabling.
- Localization.

Out of scope for the MVP:

- Blocking the native Instagram app.
- User accounts or cross-device cloud sync.
- Subscriptions or payments.
- Remote administration.
- Social features.
- A backend API.


4. DEFAULT PRODUCT DECISIONS
----------------------------

Unless the owner requests otherwise, implement these defaults:

- Blocking is enabled immediately after installation.
- Temporary unlock options are 5, 15, and 30 minutes.
- A temporary unlock applies only until its expiration timestamp.
- Restarting the browser must not reset or extend the unlock.
- If an expired unlock is detected, blocking is re-enabled immediately.
- The extension uses a neutral, calm interface rather than guilt-based language.
- All features must work without an internet connection, except loading the website being blocked.


5. RECOMMENDED TECHNICAL APPROACH
---------------------------------

Use a standards-based Manifest V3 WebExtension with plain HTML, CSS, and JavaScript. Avoid a framework and build system for the MVP unless a concrete browser compatibility issue requires one.

Recommended APIs:

- declarativeNetRequest for Instagram blocking or redirect rules.
- storage.local for enabled state and unlock expiration.
- alarms, if available and compatible, to re-enable blocking at expiration.
- A startup/event check as a fallback so expired unlocks never remain active.

Important compatibility rule:

Do not assume a Chrome-specific API is available in Safari. Keep browser-specific code isolated behind a small compatibility module. Prefer the standard `browser` namespace when Safari supports it, while providing a safe `chrome` fallback for Chromium browsers.

Suggested extension flow:

1. Extension installs.
2. Defaults are written to local storage.
3. Blocking rules are enabled.
4. User navigates to Instagram.
5. A declarative rule redirects the top-level request to block.html.
6. The popup or block page can request a temporary unlock.
7. The extension stores unlockUntil as an absolute Unix timestamp and disables the blocking rule.
8. At or after unlockUntil, the extension enables the rule again and clears unlockUntil.

Use absolute timestamps, not decrementing counters, as the source of truth. This prevents browser suspension from extending an unlock.

8. SETTINGS DATA MODEL
----------------------

Suggested versioned object:

{
  "schemaVersion": 1,
  "enabled": true,
  "unlockUntil": null
}

Rules:

- enabled = false means the user explicitly disabled blocking.
- enabled = true and unlockUntil = null means blocking is active.
- enabled = true and unlockUntil > current time means temporarily unlocked.
- enabled = true and unlockUntil <= current time means blocking must be active and unlockUntil should be cleared.
- Unknown or malformed fields should be replaced by safe defaults.

11. SECURITY AND PRIVACY REQUIREMENTS
-------------------------------------

- Follow least-privilege permissions.
- Do not request all-sites access.
- Do not use remote JavaScript or remotely hosted executable code.
- Do not collect visited URLs, page contents, credentials, or personal information.
- Do not add analytics, crash reporting, advertising, or tracking without explicit owner approval.
- Add a Content Security Policy compatible with Safari and Manifest V3.
- Escape any dynamic text rendered into HTML.
- Keep the redirect target extension-owned and deterministic.
- Treat stored settings as untrusted input and normalize them before use.


12. RISKS AND MITIGATIONS
-------------------------

Risk: Safari and Chromium differ in supported WebExtension APIs.
Mitigation: Use a compatibility module, isolate browser-specific behavior, and validate with Safari packaging warnings early.

Risk: Browser background execution may be suspended on iPhone.
Mitigation: Store an absolute unlock timestamp and verify it whenever the extension wakes, popup opens, or block page loads.

Risk: The user expects the native Instagram app to be blocked.
Mitigation: State clearly in the README and UI that the MVP blocks the website in Safari only.

Risk: Instagram introduces additional domains.
Mitigation: Begin with instagram.com and its subdomains. Add other domains only when needed, with explicit justification and minimal permissions.

Risk: App Store review rejects unclear permissions or behavior.
Mitigation: Keep permissions minimal, provide a clear privacy policy, explain the blocking behavior, and test through TestFlight first.
